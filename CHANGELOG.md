# Changelog

## 1.0.1 — 2026-11-02

Security- and conformance-focused revision. No new syntax. All changes
verified by the four-implementation differential harness
(`tests/conformance/` + fuzz).

### Specification

- **§7.3 float tie rule corrected**: shortest round-trip ties pick the
  spelling **closest to the exact binary value** (equidistant → even last
  digit). The previous "banker's even" wording did not match what CPython /
  V8 / Go emit (differential measurement: 61/61 ties resolved by
  closeness, 18/61 by evenness) and would have made conforming
  implementations diverge from all three hosts.
- **§5.9/§7.2 fractional seconds**: an all-zero fraction is removed
  entirely (`.000` → gone). The 1.0 draft's "keep `.0`" rule required a
  presence flag that no value model carries and no implementation had.
- **§6 ABNF**: base prefixes `0x/0X`, `0o/0O`, `0b/0B` and the exponent
  marker `e/E` accept both cases (matching every implementation and the
  §5.5 prose); everything else stays case-sensitive. `map` / `sexpr`
  element separators relaxed from `1*WS` to `*WS` (matching the §4.3
  token-boundary rule: `{:a[1 2]}` is valid).
- **§7.3 `\u{HEX}`** escapes use uppercase hex digits (matching all four
  implementations).
- **§5.16 Decimal equality** defined as normalised-text equality
  (leading `+` stripped, exponent marker lowercased) instead of the
  unimplementable "numeric value + scale" rule.
- **§14 pins Unicode 15.0** for the `L*` identifier classes (was a
  dangling reference).

### All implementations

- `equals(a, b)` (§5.16) implemented: iterative, NaN ≢ NaN, `-0.0 ≢ 0.0`
  (bit identity), `42 ≡ 42n`, Binary compares bytes.
- Lossless JSON decoding now enforces the §9 limits (depth, total items,
  items per collection, string bytes, int digits) on every entry point and
  rejects duplicate object keys with `WEFT_SYNTAX_JSON_DUPKEY` (§11.2.5).
- Lexical JSON reading (SPEC §11.2.1 rule 4 / §11.3): `1` vs `1.0` is
  decided by token text, not host float value.
  - Python: `loads_json` (lossless by default) with `object_pairs_hook`,
    `parse_int`/`parse_constant` hooks and a string-aware depth pre-scan.
  - TypeScript: new `parseJsonLexical` reader + `loadsJson` (lossless by
    default); `fromJsonLossless`/`fromJson` are now iterative.
  - Rust: new `parse_json_lexical` reader + `loads_json` /
    `loads_json_lossless`.
  - Go: `LoadsJSON` / `LoadsJSONLossless` (+`WithLimits` variants) over the
    ordered token walker.
- Canonical soft-wrap counts Unicode code points in all four
  implementations (§7.2; TS previously counted UTF-16 units, Rust/Go
  UTF-8 bytes).
- Datetime literals terminate at `"` (§4.3): `[#2026-11-02"a"]` parses.
- Decimal `+` sign is stripped at construction in all four (§7.2, §5.16).
- Binary canonical output is always `base64:` (§5.8/§7.2).

### Per-implementation fixes

- **Python**: shipped the previously missing `weft/validators.py`
  (base64 canonical check, `-?[0-9]+` payload shape, §7.3 escape set);
  `$bigint`/`$int-big` payloads up to `max_int_digits` decode via chunked
  conversion (no longer capped at CPython's 4300-digit `int()` limit);
  `loads_json` rejects `NaN`/`Infinity`, converts huge integer tokens
  safely, and maps host exceptions to Weft errors; CLI `to-json` /
  `from-json` default to the lossless mapping (`--lossy` opts out);
  stdlib `date`/`datetime` with year < 1000 format zero-padded;
  schema `unique` uses bit-identity for floats; `DECIMAL` tokens carry
  `byte_offset`.
- **TypeScript**: lossy `toJson` no longer drops `__proto__` map entries
  (null-prototype objects + `defineProperty`, same as the lossless path);
  strict-canonical key sort uses code-point order on all inputs.
- **Rust**: identifier classes use the real Unicode `L*` general category
  (previously `is_alphabetic && !is_numeric`, which admitted
  Other_Alphabetic combining marks such as U+0345); float formatting
  implements the §7.3 tie rule exactly (big-integer midpoint comparison)
  instead of delegating to `std` `Display`; `serde_json` is pinned with
  `preserve_order`; lossless `$map` decoding keeps insertion order.
- **Go**: the ordered JSON token walker is depth-bounded — deeply nested
  input now fails with `WEFT_LIMIT_DEPTH` instead of exhausting the
  goroutine stack and aborting the process; `FromJSON` understands
  `json.Number` (lexical int/float) and `*MapOrdered`.

### Packaging

- Build manifests shipped for all four implementations (`pyproject.toml`,
  `package.json`+`tsconfig.json`, `Cargo.toml` with
  `serde_json/preserve_order` pinned, `go.mod`).
- Language-neutral conformance corpus (`tests/conformance/`) and CI that
  rebuilds all four implementations from this repository and runs the
  corpus plus differential fuzz on every change.
- `SECURITY.md` with a reporting route (SPEC §10.9 now resolves).

### Infrastructure (new in 1.0.1)

- `tests/conformance/`: language-neutral conformance suite — 215-case corpus
  generated by 4-way agreement, byte-exact canonical checks, lossless-JSON
  round-trip identity (canonical bytes; `equals()` additionally, NaN-aware).
- `tests/fuzz/diff_fuzz.py`: deterministic differential fuzzer (structural
  documents + random float64 bit patterns) across all four implementations.
- `tests/check_package.py`: package completeness + version-lockstep check
  (guards the missing-module bug class found in review).
- `.github/workflows/ci.yml`: builds all four implementations, runs
  self-tests, conformance, fuzz, and completeness checks on every push.
- `SECURITY.md` (threat model + private reporting; resolves SPEC §10.9),
  `README.md`, `LICENSE` (MIT).
- Per-implementation self-tests covering every 1.0.1 regression class.

## 1.0.1-rc2 (external review round 3 fixes)

### P1
- **schema `:pattern` is now matched by a linear-time Thompson-NFA engine**
  (`weft.repat`, Python — the only implementation with the schema
  validator). The previous lint + wall-clock-timeout approach could not
  stop a backtracking host engine that holds the GIL; the new engine
  cannot backtrack, needs no timeout, and rejects out-of-subset patterns
  (backreferences, lookaround, named groups, inline flags) with
  `WEFT_SCHEMA_PATTERN`. `\d`/`\w`/`\s` are pinned to ASCII sets.

### P2
- **dumps/loads defaults are symmetric**: `dumps_json` (Python),
  `dumpsJson` (TypeScript) now default to the lossless §11.2 mapping,
  matching `loads_json`/`loadsJson`; pass `lossless=False` /
  `{lossless: false}` for §11.3. Go gains `DumpJSONLossless` as the
  write-side pair of `LoadsJSONLossless`.
- **JSON reader limits split into representation vs value layers**
  (TS reader, Go `decodeAnyOrdered`; Python's pre-scan was already
  2x-based): tag names, `$sexpr`'s leading tag element, and the 2-key
  `$typed`/`$bin` payload objects no longer count against
  `max_items_per_coll`/`max_string_bytes`; the exact §9 limits are
  enforced against converted Weft values. SPEC §9 now states this rule.
- **Every value-level entry point enforces §9 limits and Unicode
  validity**: `from_json`/`from_json_lossless` (Python), `fromJson`/
  `fromJsonLossless` (TS — including lone-surrogate rejection on host
  strings), `FromJSON`/`FromJSONLossless` (Go — rejects invalid UTF-8
  such as WTF-8 surrogate bytes; new `FromJSONWithLimits`), and Rust's
  `from_json*` (now ctx-threaded; new `from_json_with_limits`,
  `from_json_lossless_with_limits`). Python's `loads_json` converts a
  host `UnicodeEncodeError` on lone-surrogate input into
  `WEFT_SYNTAX_JSON`.
- **CLI preserves bytes**: file input is read without universal-newline
  translation (CRLF inside raw/triple strings survives), and canonical
  output is byte-identical across stdout / `-o` / `--in-place`, always
  ending in exactly one LF.
- **Python parser honours raised `max_depth`**: `parse`, the formatter,
  `to_json(_lossless)` and the stdlib JSON decode now run under a
  recursion-headroom guard sized to the depth limit; a depth the limits
  admit parses, formats and round-trips (verified at 1024), and a
  RecursionError that still escapes surfaces as `WEFT_LIMIT_DEPTH`.
- **raw/triple strings reject literal DEL and C1** (SPEC §5.7) in all
  four implementations; dquote strings are unchanged per SCHAR.
- **TS `$float` payloads use the strict §7.3 formatter** (`1e-07`,
  `1e+20`) — `floatCanonicalText` now delegates to `formatNumber`.
- **Go**: `FromJSONLossless(ToJSONLossless(v))` works directly (the
  ordered-map marshal adapter and raw safe-range `*big.Int` are accepted
  by the decoder); the lossy loader no longer swallows non-EOF trailing
  errors (`"1 x"`, `"1 \"unterminated"` are rejected).
- **hex `$bin` payloads are strict** in Python too (no whitespace —
  `bytes.fromhex` leniency is pre-validated away); SPEC §11.2 now spells
  out canonical-payload rejection for both encodings.

### Specification
- §4.3: `:` added to the token-boundary list (`[foo:bar]` ≡ `[foo :bar]`,
  matching all implementations).
- §5.7: the control-character paragraphs are now consistent (TAB/LF/CR
  are the exact literal exceptions in TRIPLE/RAW).
- §7.1: NaN carve-out for the fidelity invariant (round-trip identity
  for NaN-bearing documents is canonical-byte identity, since §5.16
  defines `nan ≢ nan`); new paragraph separating the byte-determinism
  guarantee from `≡`-equality (equal values do NOT hash identically —
  `0` vs `0n`).
- §7.3: map-key sort note corrected (code-point order equals UTF-8 byte
  order for scalar sequences; it is UTF-16 order that differs); the
  fixed-point window example now uses `9999999999999998.0` (`1e16`
  itself emits `1e+16`).
- ABNF: `kw-name` spelled out without pseudo-set-subtraction, and the
  sign-start branch now admits bare `:+` / `:-`.
- §9: JSON-interop early-reject semantics defined (decode phase bounded
  by `max_size_bytes`; representation-level structural caps may be
  `2x + slack` with exact limits at conversion).
- §14: explicit interoperability caveat for letters assigned after
  Unicode 15.0.

### Tests / tooling
- Conformance: `tolossless` payloads are now normalized (compact,
  key-sorted) and byte-compared across all four implementations for
  every valid corpus case — this is the check that would have caught the
  TS `$float` payload bug. 16 new corpus cases (DEL/C1 in raw/triple,
  CRLF preservation, `foo:bar` boundary, float payload shapes, hex
  whitespace, trailing JSON tokens, reversed surrogates). Corpus: 231
  cases, 615 checks per implementation.
- Self-tests extended with regressions for every fix above; README's
  example now parses (the binary literal is `b"base64:..."`) and the
  fuzzer's atom list uses real syntax; `check_package.py` and the
  runners read files as UTF-8 explicitly (Windows cp932 default).

## 1.0.1-rc3 (external review round 4 fixes)

### Pattern engine hardening (Python schema validator)
- Hostile patterns can no longer leak host exceptions or exhaust
  resources at compile time: `\u{...}` escapes are lexed as 1–6 ASCII
  hex digits only (no `int()` leniency — `+`, `_`, non-ASCII digits
  rejected), `{m,n}` counters are ASCII-digit-only and length-capped
  before conversion, group nesting is capped at 64, and the pattern
  source is capped at 10,000 code points. Anything unexpected still
  surfaces as `WEFT_SCHEMA_PATTERN`, never ValueError/RecursionError.
- Character-class ranges are sorted and coalesced at compile time and
  matched by binary search — `([aaa…a]|b)*` on a long input went from
  non-terminating (within 3 s) to linear. A single-code-point escape
  (`\x61`) is now a valid range endpoint; multi-char classes (`\d`)
  still are not.
- The normative subset, semantics and limits now live in
  **spec/SCHEMA-PATTERN.md**; repat's docstring no longer points at the
  wrong SPEC section.

### Python: recursion eliminated, not raised
- `sys.setrecursionlimit` is **never touched** anymore (the rc2 guard
  raced across threads and could reject valid input or leave the limit
  altered). The parser, pretty/strict formatters and `to_json(_lossless)`
  now run as generators on an explicit heap stack (`weft._trampoline`),
  and JSON text IO moved to a new iterative token-level reader/writer
  (`weft.jsonio`) — the same lexical-reader design as the TS/Rust/Go
  implementations, with duplicate-key rejection, digit limits, lone
  surrogate rejection and structural caps applied **while reading**.
  Any §9-admitted depth (verified at max_depth=1024) parses, formats,
  and JSON-round-trips on every host, independent of interpreter
  version or thread timing. Cost: the pure-Python JSON reader is ~20x
  slower than the C stdlib scanner (~0.4 s / 1.3 MB) — the price of
  conforming, interruption-free behavior in the reference impl.
- `int_digits_exceed` used an over-estimate of log10(2) for its lower
  bound and falsely rejected exact-boundary integers (e.g. `1<<100000`
  with `max_int_digits=30103`); it now brackets with safe under/over
  estimates and settles the window with one exact comparison.

### TypeScript
- The JSON reader's string "structural cap" is gone: input is already
  bounded by `max_size_bytes`, and the cap wrongly rejected long
  Symbol/Keyword/map-key identifiers that Weft's own text parser
  accepts. Role-specific limits remain at conversion.
- `fromJsonLossless` now applies `max_int_digits` to the direct
  `bigint` branch (previously only number/JsonNum).

### Rust / Go
- One Weft value now bumps `max_total_items` exactly once: Rust's
  scalar-tag bridge and Go's `*MapOrdered` re-dispatch no longer
  double-count (`{"$sym":"a"}` loads under `max_total_items=1`).
- Rust `from_json(_lossless)` decoded-number branches apply
  `max_int_digits`.

### Packaging / docs
- LICENSE copyright: mossbenchlab. Go module path:
  `github.com/mossbenchlab/weft/impl-go`.
- §11.2.2 now references §7.1's NaN carve-out explicitly. SECURITY.md's
  guarantees updated to cover pattern compilation, concurrency, and the
  §9 JSON-interop limit semantics.
- Self-tests: hostile-pattern battery, concurrent deep+shallow parse
  check (recursion limit must stay untouched), digit-boundary checks,
